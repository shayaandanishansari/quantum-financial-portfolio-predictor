QDPG — Encoding Strategy

Why the Current Angle vs. Amplitude Comparison is Broken

The two QDPG variants are not measuring the same thing. This document explains the specific ways they differ, why any performance gap is currently uninterpretable, and what a fair comparison looks like.

The Current Setup

Both models take a rolling window of log-returns — 30 days across 15 assets, giving 450 values per input — and produce a portfolio allocation over those 15 assets. The quantum actor is the differentiating component. Everything else (the DDPG training loop, the critic, the reward function) is shared.

The two variants are configured as follows:

Property Angle Encoding Amplitude Encoding
Preprocessing PCAWithNormalization → 15 values radial_to_linear → 1,800 values
Values entering circuit 15 1,800
num_qubits 15 ~11
num_weights 30 60
Circuit encoding RY(feature[i]) on qubit i, one-to-one StatePrep — all values as amplitudes

These are not two variants of the same experiment. They receive different data, processed differently, through circuits of different size and parameter count. Any performance difference between them could come from the encoding strategy, the preprocessing, the qubit count, or the weight budget — there is no way to tell which.

Two Different Lossy Steps

A common framing of this comparison is that amplitude encoding is more precise because it encodes more data. This is misleading. Both encodings are lossy — they just lose different information at different points.

Angle encoding loses information at preprocessing

PCA compresses the 450-value window down to 15 principal components. This is an irreversible projection. The 435 discarded dimensions are gone before the circuit ever runs. The rotation angles are then mapped faithfully — the circuit encoding itself is exact — but it is operating on an already-impoverished input.

Amplitude encoding loses information at the circuit

AmplitudeEncoding wraps PennyLane's StatePrep, which requires a unit-norm state vector. The input is therefore divided by its L2 norm before being loaded into the circuit. This means only the direction of the feature vector is preserved — its magnitude is destroyed. Two windows that are scalar multiples of each other look identical to the circuit.

Angle encoding discards variance (PCA). Amplitude encoding discards scale (L2 normalisation). Neither is strictly more precise. They answer different questions about the input.

Why Angle Encoding Cannot Handle the Full Window

Standard angle encoding requires one qubit per feature. Encoding the full 450-value window would need 450 qubits. On a classical statevector simulator, each additional qubit doubles the state dimension: 2450 complex amplitudes is not a computation that exists in the physical universe. This is why PCA was used — not because it is a good idea, but because it was the only way to make angle encoding tractable.

Amplitude encoding has no such constraint. It uses log2(n_features) qubits to encode n_features values. For 450 inputs that is ceil(log2(450)) = 9 qubits. For 1,800 inputs (after radial_to_linear) it is 11 qubits. Amplitude encoding is exponentially more data-efficient in terms of qubits, which is one of its theoretical appeals.

This asymmetry was the root cause of the unfair comparison: angle encoding was constrained to 15 features not by design but by simulation cost.

The Fix: Stacked Angle Encoding

StackedAngleEncoding already exists in this codebase (quantum_neural_network.py:66–118). It breaks the one-qubit-per-feature constraint by cycling through qubits repeatedly: 

# 450 features, 15 qubits → 30 passes

Pass 1:   RY(data[0])  → qubit 0
          RY(data[1])  → qubit 1
          ...
          RY(data[14]) → qubit 14
          ── CNOT entanglement (reverse linear) ──

Pass 2:   RY(data[15]) → qubit 0   # same qubit, new value
          RY(data[16]) → qubit 1
          ...
          RY(data[29]) → qubit 14
          ── CNOT entanglement ──

          ... 28 more passes ...

Pass 30:  RY(data[435]) → qubit 0
          ...
          RY(data[449]) → qubit 14
          ── (no entanglement after final pass) ──

All 450 values are encoded. No PCA. No dimensionality reduction. The circuit remains 15 qubits.

Important caveat. Each pass overwrites the rotation state of the qubit from the previous pass. RY(data[15]) on qubit 0 does not "remember" RY(data[0]). What carries information forward between passes is the entanglement — the CNOT layers leave quantum correlations in the joint state that the next rotation layer then acts on. Earlier data survives only as residual entanglement, not as a stored value.

This is a genuine limitation. It is weaker than the amplitude encoding guarantee of encoding every value simultaneously. But it is far stronger than discarding 97% of the data via PCA.

What a Fair Comparison Looks Like

A controlled experiment isolates one variable. The variable of interest is the encoding strategy — how the circuit loads data into the quantum state. Everything else should be held constant:

  • 1
    Same input Both receive the raw 450-value window (30 days × 15 assets), z-score standardised per feature. No PCA. No radial_to_linear expansion.
  • 2
    Same information content The same 450 numbers enter both circuits. The only question is how each circuit loads them into a quantum state.
  • 3
    Matched parameter budget num_weights is set proportionally to num_qubits, so neither circuit has more learnable capacity than the other per qubit.
  • 4
    Single variable: encoding strategy Stacked angle encodes via sequential rotation passes. Amplitude encodes via state preparation. That difference — and only that difference — is what the performance comparison will reflect.
Property Stacked Angle (proposed) Amplitude (proposed)
Input 450 values, z-score standardised 450 values, z-score standardised
Preprocessing standardize only (stateless) standardize only (stateless)
num_qubits 15 9 = ceil(log₂(450))
num_weights proportional to 15 qubits proportional to 9 qubits
How data enters circuit 30 rotation passes × 15 qubits, CNOT between each pass StatePrep — 450 values as state amplitudes (unit-norm)
Information loss Earlier passes survive only as entanglement residue Magnitude (L2 norm) is discarded by normalisation

What Will Be Implemented

The changes to MAIN.py are minimal. Both model blocks are updated to use the same preprocessing and the appropriate encoding: 

# BEFORE — Angle Encoding (unfair)
pca = PCAWithNormalization(n_components=len(tickers))
pca.fit(training_windows)
model = DDPG(
    encoding='angle',
    input_transformation=pca,
    transformed_input_size=len(tickers),
    num_weights=30,
)

# AFTER — Stacked Angle Encoding (fair)
model = DDPG(
    encoding='stacked_angle',
    input_transformation=standardize,
    # no transformed_input_size — full 450 values go in
    num_weights=proportional to 15 qubits,
)
# BEFORE — Amplitude Encoding (unfair)
model = DDPG(
    encoding='amplitude',
    input_transformation=radial_to_linear,   # 450 → 1800
    num_weights=60,
)

# AFTER — Amplitude Encoding (fair)
model = DDPG(
    encoding='amplitude',
    input_transformation=standardize,        # 450 → 450
    num_weights=proportional to 9 qubits,
)

The result is a controlled experiment where the only difference between the two models is how they load data into a quantum state. Performance differences will, for the first time, actually be interpretable as a property of the encoding strategy.
