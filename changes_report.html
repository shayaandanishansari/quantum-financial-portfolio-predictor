1Encoding Strategy & the Fair Comparison

MAIN.py · predictors/input_transformations.py · predictors/quantum_neural_network.py

The base repo had a single quantum model ('QDPG') using amplitude encoding with a 4× feature expansion. The current version replaces it with two models designed to isolate the encoding mechanism — each given the preprocessing its encoding actually needs (bounded angles for the angle circuit, a unit-norm state for amplitude).

Before — single, confounded model

model = DDPG(
    # forecast adds to input → 555 vals
    forecast_window=7,
    batch_size=1,
    predictor=QuantumNeuralNetwork,
    num_weights=60,
    encoding='amplitude',
    input_transformation=radial_to_linear,
    # num_qubits auto → ~11–12
)

After — two models, only encoding differs

model = DDPG(
    forecast_window=0,            # 450 vals
    batch_size=32,
    predictor=QuantumNeuralNetwork,
    critic_predictor=NeuralNetwork,
    num_weights=NUM_WEIGHTS,     # 30
    encoding='stacked_angle' / 'amplitude',
    input_transformation=normalized_arcsin  # angle: bounded
                       / standardize,     # amplitude
    num_qubits=len(tickers),   # 15
)

Supporting code

  • A transformed_input_size parameter was added to QuantumNeuralNetwork.__init__ (so a preprocessing step that changes the input dimension can declare its output size).
  • PCATransform and PCAWithNormalization classes were added to input_transformations.py. These powered an intermediate angle-encoding + PCA exploration that has since been superseded by stacked_angle + normalized_arcsin; the classes remain in the file but are no longer wired into MAIN.py.

Why The base setup confounded the encoding with its preprocessing, qubit count, and parameter budget — so any performance difference couldn't be attributed to the encoding itself. Equalising the qubit count, parameter budget, critic, batching, and data window leaves the encoding mechanism as the variable of interest.

Refinement — bounded angles for the stacked encoder

A first run used standardize for both models. Amplitude trained fine, but the stacked-angle model behaved like an untrained network — wildly variable, Sharpe ≈ 0. The cause: raw z-scores (~±4, unbounded) were fed directly as RY rotation angles, and each qubit accumulates 30 of them across the 30 stacked passes, over-rotating the circuit into a regime where it couldn't learn. The fix was to give the angle circuit bounded inputs via normalized_arcsin (min-max → arcsin → [−π/2, π/2]); amplitude keeps standardize since it L2-normalizes into a state and doesn't care about angle bounds.

Why Identical preprocessing is not the same as fair. Each encoding needs the preprocessing it was designed for — bounded angles for angle encoding (the original angle path used arcsin for exactly this reason), a unit-norm state for amplitude. After bounding, the stacked-angle model trains properly and the comparison becomes meaningful.

2Batched / Vectorized Training Loop

ddpg/ddpg_functions.py — the "OPTIMISED VERSION"

The base training loop processed one window at a time with state.flatten() and then sampled exactly one transition from the replay buffer — so batch_size was effectively ignored for the gradient step. The loop was rewritten to operate on full batches.

Before — one sample at a time

portfolio_allocation = self.actor(
    state.flatten())
...
replay_buffer.push((state, ...))
# sample a SINGLE transition
transition = replay_buffer.sample(1)
state = transition[0][0]
...
critic_loss = (target - q).pow(2)

After — full batch

b = state.shape[0]
state_flat = state.view(b, -1)
portfolio_allocation = self.actor(state_flat)
...
for i in range(b):           # push each
    replay_buffer.push((state[i], ...))
k = min(batch_size, len(replay_buffer))
transitions = replay_buffer.sample(k)
...
critic_loss = (target - q).pow(2).mean()
clip_grad_norm_(..., max_norm=1.0)
  • Batched forward passes for actor and critic, in both the training and validation loops.
  • Replay buffer now pushes each transition individually then samples a full batch of size min(batch_size, len) — so increasing batch_size actually takes effect.
  • Gradient clipping (clip_grad_norm_(max_norm=1.0)) added on both networks.
  • Reward fixed to a proper per-sample daily-return mean/std via state * pa.unsqueeze(1) giving (b, window) returns.

Why At batch_size=1 the model took ~one noisy gradient step per window (~1,300+ per epoch). Batching cuts gradient steps roughly 32×, stabilises the updates, and is the main reason the expensive 15-qubit simulations are now tractable; gradient clipping guards against exploding updates.

3Independent Critic Network

ddpg/ddpg_functions.py

In the base code the critic was always instantiated from the same class as the actor with the same keyword arguments — so a quantum actor forced a quantum critic. New critic_predictor / critic_predictor_kwargs arguments decouple them.

Before

critic = self.predictor(
    input_size=...,
    output_size=1,
    **self.predictor_kwargs,
)

After

self.critic_predictor = kwargs.pop(
    'critic_predictor', predictor)
...
critic = self.critic_predictor(
    input_size=...,
    output_size=1,
    **self.critic_predictor_kwargs,
)

Why Lets a quantum actor be paired with a fast classical critic, and — crucially for Section 1 — keeps the critic identical across both encoding models (NeuralNetwork(hidden_sizes=(30,))), so the critic isn't an extra confounding variable in the comparison.

4Numerical-Stability & Robustness Guards

input_transformations.py · ddpg_functions.py · metrics.py · MAIN.py · data_processing.py

Several small but important fixes prevent NaN/divide-by-zero from crashing runs or silently poisoning the cross-validation averages.

LocationBeforeAfter

Why Zero-sum portfolio allocations, zero-variance windows, constant features (min = max), arcsin's infinite-derivative endpoints, and failed ARIMA forecasts all produced NaNs or gradient spikes in the base code. The + 1e-8 guards, arcsin clamp, and NaN-aware aggregation keep a single bad fold from taking down the whole run or skewing the reported averages.

Status & Caveats

  • After the angle-bounding refinement (§1), the stacked-angle model trains properly: the latest 3-fold run gives stacked-angle ≈ 22% vs amplitude ≈ 8% profit p.a., reversing the earlier untrained result. (Earlier amplitude runs scored higher with more CV folds / more training data; the ranking is dataset-budget dependent.)
  • The angle-bounding change (normalized_arcsin + the min-max/arcsin guards) is currently an uncommitted working-tree edit on top of HEAD 46b82bb.
  • The PCATransform / PCAWithNormalization classes remain in input_transformations.py as a deliberate artifact of the intermediate angle+PCA exploration; they are no longer referenced by MAIN.py.
  • radial_to_linear is still used by the 'Quantum Q-Learning' model, so it was intentionally kept.
