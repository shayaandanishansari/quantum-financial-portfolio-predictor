Fair Encoding Comparison: Stacked Angle vs Amplitude

Two fixes from v1: radial_to_linear is dropped entirely, and both circuits use the same number of qubits. The result is a genuinely controlled experiment where encoding strategy is the only variable.

What Changed from v1

Property v1 (broken) v2 (fixed)

Amplitude preprocessing radial_to_linear 450 → 1,800 z-score only, all 450 in
Amplitude num_qubits 9 = ceil(log₂ 450) 15 — same as stacked angle

Why radial_to_linear Is Dropped

radial_to_linear existed to solve a real problem with amplitude encoding: after z-score standardisation, all input vectors have elements of roughly similar magnitude. When you L2-normalise such a vector — which amplitude encoding must do before StatePrep — every window ends up pointing in a similar direction in Hilbert space. The circuit sees little variation between days.

The [X, X², sin(X), cos(X)] expansion was a fix for that. It spreads inputs into a richer subspace before normalisation so the circuit can distinguish between different market conditions.

The problem: this is feature engineering that only amplitude encoding gets. It is not a property of the encoding strategy — it is a head start. Keeping it makes amplitude encoding look better than it actually is for the raw data.

For a fair comparison it is dropped. Both circuits receive identical input. If amplitude encoding is genuinely better, it should show without the assistance. If it needs radial_to_linear to be competitive, that is itself a meaningful finding.

Why Both Use 15 Qubits

The measurement step reads one expval(PauliZ) per qubit and maps directly to portfolio weights — one per asset. There are 15 assets, so you need at least 15 qubits to produce 15 outputs without any extra classical layer.

The v1 plan gave amplitude encoding 9 qubits because that is the theoretical minimum to encode 450 values (2⁹ = 512 ≥ 450). But with only 9 qubits you can only measure 9 values. Closing that gap with a classical 9 → 15 linear layer would give amplitude encoding an extra trainable component stacked angle does not have — another unfair advantage.

The fix is simple: both circuits use 15 qubits. Amplitude encoding pads its 450 values to 2¹⁵ = 32,768 with zeros before normalisation. The zero-padded entries carry no information and do not affect the encoded state — they are just structural padding. The encoding still loads all 450 real values as state amplitudes.

Amplitude encoding retains its theoretical advantage: it encodes all 450 values simultaneously as a single quantum state, while stacked angle processes them in 30 sequential passes. The qubit count is now equal; the encoding mechanism is the only remaining difference.

The Fair Setup

  • 1
    Same input Both receive the raw 450-value window (30 days × 15 assets of log-returns), z-score standardised per feature. No PCA. No radial_to_linear.
  • 2
    Same qubit count Both circuits use 15 qubits. Output is 15 PauliZ expectation values → softmax → portfolio weights. No extra classical layers on either side.
  • 3
    Same parameter budget num_weights set to the same value for both, proportional to 15 qubits. Neither circuit has more learnable capacity than the other.
  • 4
    One variable: encoding strategy Stacked angle encodes via 30 sequential rotation passes with CNOT entanglement between each. Amplitude encodes via a single StatePrep over all 450 values simultaneously. That difference — and only that difference — is what any performance gap will reflect.

# AFTER

    encoding='amplitude',
    input_transformation=standardize,        # stateless, all 450 in

    num_weights=NUM_WEIGHTS,                 # same shared constant
    # AmplitudeEncoding pads 450 → 2¹⁵ internally before StatePrep
)

One shared constant. Define NUM_WEIGHTS once at the top of MAIN.py and pass it to both models. Any performance difference now cannot be attributed to one model having more parameters than the other.

What the Results Will Actually Tell You

With this setup, a performance difference between the two models reflects a genuine property of the encoding strategy:

  • A
    If stacked angle wins Temporal ordering matters. Processing the 30-day window sequentially — day by day, with entanglement carrying context forward — extracts more useful structure than loading all values simultaneously without order.
  • B
    If amplitude wins Simultaneous encoding of all values as state amplitudes is more expressive than sequential passes. The recency bias in stacked angle is a meaningful handicap, and the loss of magnitude information from L2 normalisation does not matter much for this task.
  • C
    If they are equal The encoding strategy is not the bottleneck. Attention should shift to circuit depth, ansatz design, or the classical components of DDPG.
